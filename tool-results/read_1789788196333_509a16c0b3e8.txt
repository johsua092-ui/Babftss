   258→## 4. PENGETAHUAN TEKNIS MAHAL (jangan ulangi risetnya)
   259→
   260→Hasil pengukuran langsung ke `node_modules/three/examples/jsm/controls/TransformControls.js`.
   261→
   262→### Struktur TransformControls 0.185
   263→```
   264→transformControls
   265→  ._root                          ← hasil getHelper(), di-add ke scene
   266→      ._gizmo                     ← TransformControlsGizmo
   267→          .gizmo.translate        ← VISUAL panah      (yang dimodifikasi)
   268→          .gizmo.rotate           ← VISUAL cincin
   269→          .gizmo.scale            ← VISUAL scale
   270→          .picker.translate        ← AREA KLIK (invisible) — JANGAN disentuh
   271→          .picker.rotate
   272→          .helper.translate        ← garis bantu putih
   273→      ._plane                     ← bidang bantu untuk hitung drag
   274→```
   275→
   276→### 5 JEBAKAN PALING MEMATIKAN
   277→**1. `handle.position` DITIMPA SETIAP FRAME** (baris 1613):
   278→`handle.position.copy(this.worldPosition)` → set manual selalu hilang.
   279→Diverifikasi: set (9,9,9) → jadi (0,0,0). → Offset posisi WAJIB lewat `geometry.translate()`.
   280→
   281→**2. `handle.visible = true` DIPAKSA SETIAP FRAME** (baris 1611):
   282→Menyembunyikan sekali langsung dibatalkan frame berikutnya.
   283→→ Bungkus `_gizmo.updateMatrixWorld`, terapkan SESUDAH fungsi asli:
   284→```javascript
   285→const originalUpdate = gizmoRoot.updateMatrixWorld;
   286→gizmoRoot.updateMatrixWorld = function (force) {
   287→  originalUpdate.call(this, force);   // biarkan yang asli jalan dulu
   288→  /* ...baru terapkan penyembunyian/pengaturan di sini... */
   289→};
   290→```
   291→
   292→**3. `setupGizmo()` MEM-BAKE ROTASI KE GEOMETRY** (baris 1538-1540):
   293→Setelah itu bounding box sudah world-space: shaft X → sizeY cuma 0.0130, dsb.
   294→→ Jangan pakai tinggi-Y untuk klasifikasi. **Ukur extent pada sumbu handle-nya
   295→sendiri** (handle 'X' → ukur `x`). Shaft ≈0.5, cone ≈0.1.
   296→→ `handle.isMesh` TIDAK bisa membedakan garis dari kerucut (lineGeometry2 juga Mesh).
   297→
   298→**4. Mode rotate: setiap handle diputar CAMERA-ALIGN** (baris 1831-1853):
   299→Cincin penuh tidak kelihatan berubah, tapi bola yang menempel JELAS bergeser.
   300→→ Kunci quaternion bola ke basis gizmo, lalu **WAJIB**
   301→`rotateObj.updateMatrixWorld(true)` karena `super.updateMatrixWorld()` sudah
   302→dipanggil di akhir fungsi asli (baris 1902).
   303→
   304→**5. `material.color` gizmo DITIMPA TIAP FRAME dari cache `_color`** (baris 1874-1878,
   305→ditemukan 2026-09-07, commit `f2b6ca1`):
   306→`updateMatrixWorld()` menyimpan warna asli ke `material._color` lalu menimpa
   307→`material.color.copy(material._color)` SETIAP FRAME. Mengubah `handle.material.color`
   308→langsung → 1 frame kemudian BALIK ke warna lama. Ini sumber kegagalan panjang
   309→fitur "warna gizmo Clone/Mirror" (banyak AI menyerah / malah merusak fitur lain):
   310→setGizmoColor() lama melaporkan `changed:12` (lulus palsu) tapi layar tak berubah.
   311→→ CARA BENAR: API publik `tc.setColors(x, y, z, active)` (baris 947) —
   312→satu-satunya jalur yang JUGA memperbarui cache `_color` (baris 962-969).
   313→Semua handle panah/bola SHARE material dari `materialLib`, jadi satu panggilan
   314→menjangkau semuanya. Slot `active` (warna highlight hover/drag) ikut diisi
   315→supaya panah tidak "balik kuning" saat di-hover. Reset default:
   316→`tc.setColors(0xff0000, 0x00ff00, 0x0000ff, 0xffff00)`.
   317→PENGECUALIAN (Phase 51, commit `e6045e8`): bola scale #EFBF04 memakai material
   318→BARU per sumbu — BUKAN share materialLib — supaya warnanya kebal terhadap
   319→setColors() clone/mirror. Highlight hover tetap bekerja karena baris 1884
   320→meng-copy `materialLib.active.color` langsung ke handle aktif.
   321→
   322→**5b. Mode scale DIPAKSA space='local'** (baris 1585: `const space = (this.mode
   323→=== 'scale') ? 'local' : this.space;`) WALAU tc.space='world'. Konsekuensi:
   324→gizmo scale mengikuti worldQuaternion object, sementara pointStart tetap
   325→world space → deteksi SISI (untuk solo drag) WAJIB un-rotate pointStart
   326→dengan inverse worldQuaternion SELALU di mode scale (Move hanya perlu saat
   327→space==='local'). Tanpa ini, block yang dirotasi 90° membuat deteksi sisi
   328→salah/kabur (terukur: komponen 0.000).
   329→
   330→### Angka penting Move gizmo (translate)
   331→```
   332→cone (arrowGeometry)  : CylinderGeometry(0, 0.04, 0.1, 12)   center ±0.55
   333→shaft (lineGeometry2) : CylinderGeometry(0.0075,0.0075,0.5,3) center ±0.25
   334→Bawaan: 6 cone + hanya 3 shaft (sisi + saja)  ← INI SUMBER BUG
   335→Mirror ke sisi negatif: rotasi 180° thd sumbu PERPENDICULAR
   336→  x → putar thd Y  |  y → putar thd X  |  z → putar thd X
   337→Determinan +1 → winding aman, TIDAK perlu DoubleSide
   338→```
   339→
   340→### Angka penting Rotate gizmo
   341→```
   342→Bawaan punya 5 handle:
   343→  XYZE : cincin abu-abu #787878 PENUH r=0.5
   344→  X    : busur merah SETENGAH (arc 0.5), bidang YZ
   345→  Y    : busur hijau SETENGAH, bidang XZ
   346→  Z    : busur biru SETENGAH, bidang XY
   347→  E    : cincin kuning #ffff00 PENUH r=0.75
   348→Cincin penuh: TorusGeometry(0.5, 0.0075, 3, 64, 2π) + rotateY(π/2) + rotateX(π/2)
   349→  rotasi tambahan: X=none, Y=[0,0,-π/2], Z=[0,π/2,0]
   350→  cek berhasil: bbox 1.015 x 1.015 pada 2 sumbu (bukan 1.015 x 0.507)

   359→### BUG SEJARAH — TransformControls Clone/Mirror (Phase 50 v9, 2026-09-06)
   360→
   361→**Akar Masalah:**
   362→TransformControls intercept drag SEBELUM click handler fire. Saat user switch
   363→dari Move ke Clone/Mirror:
   364→- Gizmo masih attach ke block lama dari operasi Move
   365→- User klik-tahan-geser → TransformControls drag block lama (bukan ghost clone)
   366→- `onWindowMouseUp` exit early karena `transformControls.dragging = true`
   367→- Branch clone di click handler tidak pernah tercapai → ghost tidak ter-create
   368→- Hasil: Clone tidak bekerja, terasa seperti Move biasa
   369→
   370→**Solusi yang BENAR** (commit `d7e0938`):
   371→```javascript
   372→// Di useEffect yang watch tool state, saat switch ke Clone/Mirror:
   373→if ((tool === 'clone' || tool === 'mirror') && tc.object) {
   374→  const sourceBlock = tc.object;
   375→  tc.detach();   // 1. Detach dari block asli
   376→
   377→  // 2. Auto-create ghost di posisi block yang sama
   378→  if (sourceBlock && sourceBlock.userData.isBlock && !sourceBlock.userData.cloneGhost) {
   379→    const scene = threeRef.current.scene;
   380→    if (scene) {
   381→      const ghost = new THREE.Mesh(
   382→        sourceBlock.geometry.clone(),
   383→        Array.isArray(sourceBlock.material)
   384→          ? sourceBlock.material.map(m => m.clone())
   385→          : sourceBlock.material.clone()
   386→      );
   387→      ghost.position.copy(sourceBlock.position);
   388→      ghost.rotation.copy(sourceBlock.rotation);
   389→      ghost.scale.copy(sourceBlock.scale);
   390→      ghost.userData.isBlock = true;
   391→      ghost.userData.cloneGhost = true;
   392→      scene.add(ghost);
   393→      threeRef.current.blocks.push(ghost);
   394→      threeRef.current.cloneGhost = ghost;
   395→
   396→      // 3. Attach gizmo ke ghost → 6 panah muncul di ghost
   397→      tc.attach(ghost);
   398→    }
   399→  }
   400→}
   401→```
   402→
   403→**Flow yang BENAR:**
   404→1. Move → 6 panah muncul di block A
   405→2. Switch Clone → detach dari A → auto-create ghost di posisi A → attach ke
   406→   ghost → 6 panah muncul di ghost
   407→3. Drag ghost → clone bekerja (block baru ter-create)
   408→4. Klik block lain → gizmo pindah ke ghost baru
   409→
   410→**Pola Kesalahan yang HARUS DIHINDARI:**
   411→1. Terlalu cepat apply fix tanpa trace flow lengkap — jangan asumsikan masalahnya
   412→   di mana. Trace: mousedown → drag → mouseup → handler → branch mana yang fire?
   413→2. Detach gizmo saja — 6 panah hilang → UX buruk. User harus klik block dulu
   414→   baru 6 panah muncul. Tidak natural.
   415→3. Re-attach ke block yang sama — TransformControls intercept drag lagi → clone
   416→   tidak bekerja (kembali ke masalah awal).
   417→4. Tidak pikirkan UX impact — gizmo visible vs hidden, flow natural vs awkward,
   418→   user expectation.
