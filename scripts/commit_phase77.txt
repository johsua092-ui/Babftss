fix(scale-ui): Phase 77 — fix goyang saat snap + 3 desimal + koma→titik

MASALAH
Dua bug + 1 permintaan UX dari user setelah Phase 75/76:

1. BUG GOYANG: saat user scale MENGECIL dengan snap aktif, block
   "goyang goyang bergetar sampai yang paling parah bergeser dari
   posisi awal". Scale memanjang aman, tapi mengecil goyang.

2. LIMIT 3 ANGKA DI BELAKANG KOMA: user mau bisa input 0.001,
   0.002, ..., 1.263, dst (maks 3 desimal). 4 desimal (0.0001)
   "mustahil user menginput". Tapi penunjuk (hasil konversi)
   boleh banyak angka.

3. KOMA → TITIK: user mau koma "," diganti titik "." paksa di
   input field. User ketik "1,5" → auto-ubah jadi "1.5".

PENYEBAB
1. computeAnchorOffset (mode 1 side) dijalankan SETIAP FRAME dengan
   offset = (scaleNew - startScale) × halfSize. Saat snap lompat
   antar step (karena user drag), scaleNew berubah cepat → offset
   berubah cepat → posisi block berubah cepat = GOYANG. Saat scale
   membesar, offset positif (ke arah sisi +); saat mengecil, offset
   negatif (ke arah sisi −). Lompatan offset lebih terlihat saat
   mengecil karena delta negatif lebih besar magnitude-nya untuk
   step yang sama.

2. STEP = 0.01 (Phase 76) — user mau 0.001. Tidak ada validasi
   maksimal 3 desimal, jadi user bisa input 0.0001 atau 1.2634.

3. Input type="number" di browser beda-beda locale. Beberapa
   browser tidak terima koma sebagai decimal separator. User mau
   eksplisit: koma diubah paksa ke titik.

CATATAN
- BUG GOYANG adalah lesson learned lanjutan dari butir 99 kontrak
  (snap relatif ke startScale). Snap relatif supaya block tidak
  melompat saat belum drag. Tapi saat user drag + snap lompat
  antar step, computeAnchorOffset (yang pakai scale yang sudah
  di-snap) juga lompat → posisi lompat → goyang. Fix Phase 77:
  skip computeAnchorOffset saat snap aktif. Trade-off: mode 1
  side + snap = behavior mode 2 side (scale dari pusat). User
  pilih mode 1 side tanpa snap (step=0) kalau mau sisi seberang
  diam. Document di komentar Phase 77 + kontrak warisan.
- INPUT TYPE: ganti dari type="number" ke type="text" +
  inputMode="decimal". Alasan: type="number" di browser beda-
  beda locale, koma kadang tidak diterima. type="text" + manual
  onChange handler (replace koma→titik) = kontrol penuh. Tapi
  hilang fitur arrow ↑↓ bawaan browser (karena bukan type=
  number). User bisa pakai keyboard arrow normal di text field
  (kurang lebih sama UX). Trade-off acceptable supaya koma→titik
  jalan konsisten lintas-browser.
- Komentar header Phase 74 di ScaleNumberModal.jsx baris 1-58
  yang menyebut "MIN_STUDS = 0.25" + "STEP = 0.01" + "type=
  number" sekarang OUTDATED lagi (Phase 76 + 77). Tidak di-update
  untuk minimal change (lihat kontrak butir 83, 86, 93 — komentar
  header Phase lama cycle outdated lintas-Phase).
