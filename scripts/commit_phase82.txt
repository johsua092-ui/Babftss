MASALAH
Dua bug dari user:

1. Saat scale mengecil di mode 1 side, block "geser-geser! bahkan
   pindah lokasi!". User mau "blocknya diam mau dipanjangin atau
   dipendekin! harusnya absolut diam!".

2. Matematika: kalau step = 2 studs dan block 2 studs (default),
   tidak bisa mengecil (karena 2 - 2 = 0, tidak valid). User:
   "kalau saya panjangin dengan scale 2 lalu saya kembalikan lagi
   maka scale 2 ketemu ukuran asli blocknya saat ini yaitu
   panjangnya 2 maka 2 ketemu harusnya saling meniadakan dan

   besar dari 2 misal 5 atau 10 kan gak bakal bisa bukan? itu
   logika mutlak dunia ini!".

PENYEBAB
1. computeAnchorOffset (mode 1 side) menggeser pusat block supaya
   sisi seberang diam (math mode 1 side). Saat snap lompat antar
   step, offset lompat → pusat lompat → block "geser-geser /
   pindah lokasi". User mau block DIAM (BUKAN sisi seberang diam).

2. Snap Phase 79 pakai `finalScale = max(|s0 + finalStep ×
   stepScale|, minAbs)`. Kalau s0 + finalStep × stepScale = 0
   (mis. startScale 1.0 + step -1 × 1.0 = 0), finalScale = max(0,
   0.05) = 0.05 (di-clamp ke MIN_ABS_SCALE). Block mengecil ke
   0.1 studs, BUKAN tetap di default. User mau: kalau candidateScale
   < minAbs, JANGAN snap. Tetap di lastStep.

CATATAN
- BUG INI = lesson learned lanjutan dari kontrak butir 104 (SKIP
  computeAnchorOffset saat snap aktif). Phase 77 sudah implementasi
  skip, TAPI user Phase 78 komplain "sisi seberang tidak diam".
  Phase 79 kembalikan computeAnchorOffset + hysteresis. TAPI user
  Phase 82 komplain "block geser-geser". Phase 82 kembali ke skip
  (Phase 77 style) + tambah cek minimum.
- Pelajaran: user preference BISA BERUBAH antar phase. Phase 78
  mau sisi seberang diam. Phase 82 mau block diam. Konflik. Phase 82
  prioritaskan block diam karena user explicit bilang "harusnya
  absolut diam". Kalau user Phase berikutnya mau sisi seberang
  diam lagi, TANYA user pilih: block diam atau sisi seberang diam
  (tidak mungkin both di Three.js).
- Trade-off: dengan skip computeAnchorOffset saat snap aktif,
  mode 1 side + snap = behavior mode 2 side (scale dari pusat,
  sisi seberang bergerak simetris). Sisi seberang TIDAK diam.
  User Phase 78 komplain. Tapi user Phase 82 mau block diam.
  Prioritas block diam.
- Cek minimum: kalau candidateScale < minAbs, JANGAN snap. Tetap
  di lastStep. Block "tidak bisa di-scale lagi" kalau step besar.
  Implementasi: `if (Math.abs(candidateScale) < minAbs) { finalStep
  = lastStep; }`. Simple + robust.
