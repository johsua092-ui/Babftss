fix(scale-ui): Phase 78 — snap pindah ke mouseUp, fix goyang + sisi seberang diam

MASALAH
User komplain: "kok di mode 1side 2 sisi ke scale? harusnya sisi
lain diam". Phase 77 (commit 9c953ab) fix goyang dengan SKIP
computeAnchorOffset saat snap aktif — TAPI break mode 1 side
semantics (sisi seberang tidak diam, block scale dari pusat =
behavior mode 2 side). User tidak terima trade-off ini. User mau
BOTH: snap aktif + sisi seberang diam + tidak goyang.

User juga bilang: "kamu kena jebakan lagi ya? padahal kamu sudah
suru baca kontrak permanen md agar tidak kena jebakan, kenapa
masih aja kena jebakan??". Akar masalah: mental simulation flow
Phase 77 TIDAK cover case "mode 1 side + snap aktif" secara
spesifik — saya cuma cek "snap aktif → block scale smooth →
tidak goyang", TIDAK cek "sisi seberang diam atau tidak".

PENYEBAB
Phase 77 (commit 9c953ab) hapus computeAnchorOffset saat snap
aktif (untuk fix goyang). Tapi computeAnchorOffset adalah yang
buat sisi seberang diam di mode 1 side. Skip = sisi seberang ikut
scale (mode 2 side behavior). User pilih mode 1 side karena mau
sisi seberang diam — skip = break semantics.

Akar masalah yang lebih dalam: snap di applyScaleByMode (setiap
frame) + computeAnchorOffset (setiap frame, pakai scale untuk
hitung offset posisi) = CONFLICT. Saat snap lompat antar step,
scale berubah cepat → offset berubah cepat → posisi goyang.
Phase 77 pilih skip computeAnchorOffset (sacrifice sisi seberang
diam). Phase 78 pilih pendekatan lain: pindah snap ke mouseUp
(sacrifice NOTHING).
